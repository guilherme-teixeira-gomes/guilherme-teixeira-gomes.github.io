Street lighting telemetry and field operations

In production, 2024 to now

Full case study (in Portuguese)

Monitors and commands a city’s entire street lighting network. Controllers report over MQTT, every light point sits on a live map, field crews receive work orders on their phones, citizens report outages over WhatsApp, and city hall gets PDF and Google Earth (KMZ) reports.

My role. Tech Lead and sole technical owner: architecture, backend, web and both mobile apps.

Decisions worth mentioning

  • Moved the platform from single-tenant to multi-company across the API, the web app and two mobile apps, without breaking the app crews were already using in production. Tenant scope is enforced at the query layer, and legacy records were backfilled in the production database.
  • Moved report generation onto a dedicated Bull and Redis worker, so rendering a large PDF no longer restarts the web process.
  • Hardened the backend: removed N+1 queries, added the indexes the query plans called for, extracted services with 31 tests, added SonarCloud and removed hardcoded credentials.

Built with: Node.js, TypeScript, Express, TypeORM, PostgreSQL, Bull, Redis, MQTT, React, React Native (Expo), Twilio, Heroku

Smart traffic signals

In production, 2025 to now

Full case study (in Portuguese)

Remote control of city intersections across four environments: Arduino firmware, a Python gateway on a Linux mini PC reached over Tailscale, an MQTT broker and the cloud backend. It runs alongside a YOLO-based license plate recognition camera system.

My role. Architecture and implementation, from firmware protocol to cloud backend.

Decisions worth mentioning

  • Defined a strict precedence between command sources, schedule over manual command over factory mode, so the signal state is never ambiguous.
  • Tracked down a silent protocol mismatch between the gateway and the firmware and fixed the command serialization at the source.

Built with: Arduino, MQTT, Python, Flask, Tailscale, Node.js

Minha Saúde Açailândia: public health scheduling

Pilot, 2026, at one municipal clinic

A multi-tenant platform for a municipal health department: appointment scheduling, queue management and a staff dashboard, plus a citizen app and a separate tablet app for community health agents, with chat between the two.

My role. Built it from scratch. Now leading it with a second developer.

Decisions worth mentioning

  • Tenant isolation lives in the data layer through a shared tenant-aware repository, so every query is scoped by default instead of by convention.
  • Two mobile apps for two very different users, citizens on their own phones and health agents on shared tablets, over a single backend.

Built with: Node.js, Express, TypeORM, PostgreSQL, React, Vite, Ant Design, Expo, Heroku

VegaMonito: CCTV and access control

Rolling out, 2026, first clinic

A central platform for video surveillance and facial access control, where each client can have several monitored sites. It integrates Control iD face readers through their push API and Hikvision cameras, and sends alerts over WhatsApp.

My role. Architecture and backend, together with a second developer.

Decisions worth mentioning

  • The platform is the source of truth, not the hardware: people, access rules and face data live in our own database, and the readers are treated as replaceable devices.
  • Video flows through a cloud gateway on Google Cloud that pulls from the clinic’s recorder, so a copy of the footage survives even if the on-site recorder is stolen.

Built with: Node.js, PostgreSQL, React, Google Cloud (Compute Engine, Cloud Storage), Twilio, Heroku

De & Ge: restaurant operations

In production, 2026, in daily use

Live site Source code

Runs stock, purchasing, menu, sales and food cost, from daily to yearly, for a restaurant in São Paulo.

My role. Sole developer. It doubles as my FIAP postgraduate project.

Decisions worth mentioning

  • Recipe cost uses the weighted average of purchase prices, and every sale deducts stock automatically, so the food cost figure is always current.
  • Designed for staff with no technical background: a quick checkout with large dish buttons, stock shown as visual cards rather than tables, and a public menu behind a QR code.
  • A monorepo with a package shared by the API and the web app, and Clean Architecture with an explicit composition root.

Built with: Node.js, TypeScript, Express, TypeORM, PostgreSQL, React, Vite, Ant Design, Recharts, Heroku
